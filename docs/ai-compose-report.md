# Отчёт: режим «Создать» (AI Compose) и кнопка настроек клавиатуры (04.10.2026)

## 1. Итог

- В клавиатуре iOS и Android появился второй, независимый AI-режим: **✨ рядом с «+»**.
  Пользователь описывает, что написать («Поздравь директора Сакена Бакпакбековича с 55-летием…»),
  сервер пишет готовое сообщение, пользователь вставляет его в поле WhatsApp/Telegram/Instagram/Messages.
  Кнопку «Отправить» мессенджера клавиатура не нажимает.
- Ответ на скопированное сообщение (Друг / Клиент / Бизнес / Работа) работает как раньше:
  его логика, промпт и эндпоинт не менялись.
- Буфер обмена в режиме «Создать» не читается вообще — ни при открытии, ни при генерации.
- Карточка «Клавиатура» в приложении: вместо двух кнопок, ведущих в одно место, — одна
  основная кнопка, и только пока настройка не закончена.

## 4. Бэкенд

- Отдельный эндпоинт **`POST /api/v1/ai/compose`**, рядом с `/ai/reply` (так устроен API проекта).
- Свой промпт (`composeInstructions`): «пишешь готовое сообщение; входящего сообщения нет»;
  язык — язык инструкции или явно названный («на казахском»); имена, отчества, возраст, даты — как есть;
  без выдуманных фактов и без заглушек `[Имя]`; эмодзи — если просят или уместно; только текст,
  без «Конечно», «Вот ваше сообщение». Блока `incoming_message` и правил ответа в нём нет.
- Инструкция пользователя — в user-сообщении (`<request>`), правила — в developer-сообщении.
  Язык интерфейса (только проверенный код kk/ru/en/uz) — запасной вариант, когда язык инструкции
  не ясен (одни имена или эмодзи). `regenerate: true` → «напиши другую версию».
- Переиспользовано всё: провайдер, модель, таймаут, ретраи, квота, учёт токенов и стоимости,
  rate limit (`aiLimit`), аутентификация, коды ошибок. `Reply` и `Compose` идут через общий
  `Service.generate` — поведение `Reply` не изменилось (все старые тесты зелёные).
- Лимит токенов ответа для «Создать» — не меньше 700 (казахское/русское поздравление длиннее
  ответа в 180 токенов), не больше 1024; если в админке задано больше 700 — берётся админское.
- Длина инструкции — `max_instruction_length` из админки (по умолчанию 400). Длиннее —
  `400 INVALID_REQUEST`, `details {field: "instruction", max_characters}`; не обрезается молча.
- **Изменение схемы** (почему нужно): `0006_usage_mode.sql` добавляет `ai_usage_events.mode`
  (`reply` | `compose`, по умолчанию `reply`). Без него в статистике нельзя отличить созданные
  сообщения от ответов. Только `ADD COLUMN` с дефолтом: старые записи и старые бинарники не затронуты.
- Структурный лог `ai_compose_generate_success` (user_id, платформа, версия, задержка, токены);
  ошибки — существующий `ai request failed` с `mode`. Текст инструкции и сообщения нигде не пишется
  (проверено тестом по файлу БД и логам).

## 5. Контракт API

```http
POST /api/v1/ai/compose
Authorization: Bearer <access>
{"instruction": "Поздравь директора…", "language": "ru", "regenerate": false,
 "platform": "ios", "app_version": "1.3.0"}

200 {"text": "Уважаемый Сакен Бакпакбекович! …", "detected_language": "ru",
     "usage": {"daily_limit": 7, "used_today": 2, "remaining_today": 5, "resets_at": "…", "timezone": "Asia/Almaty"}}
```

Ошибки — те же коды, что у `/ai/reply`: `UNAUTHORIZED`, `DAILY_LIMIT_REACHED` / `MONTHLY_LIMIT_REACHED`,
`RATE_LIMITED`, `AI_TIMEOUT`, `AI_PROVIDER_UNAVAILABLE`, `AI_EMPTY_RESPONSE`, `INVALID_REQUEST`.
`GET /api/v1/config` → `features.compose = true`.

## 6. Клавиатура iOS

- **✨** — круглая кнопка того же вида, что «+», закреплена справа вместе с «+» (никогда не обрезается
  и не уезжает при прокрутке). Только иконка: подпись «Создать» рядом с персонами читалась как ещё одна персона.
- Ряд персон **адаптивный**: если влезают — растягиваются равномерно; если тесно — уменьшаются
  отступы; если не влезают и так — прокрутка с мягким затуханием у края, без обрезанных подписей.
- Панель «✨ Написать с AI» заменяет ряд персон: заголовок, «Новое» (когда есть что очищать), ✕;
  поле запроса на 4 строки (3 на маленьком экране; дальше прокрутка), подсказка с примером переносится;
  быстрые добавки (Поздравить, Коротко, Официально, Дружелюбно, С эмодзи, Поблагодарить, Вежливый отказ —
  пишутся в запрос, их можно править); «✨ Написать» активна, только когда запрос не пустой.
- Результат: поле до 8 строк с прокруткой (ответ «Создать» обычно длиннее ответа на сообщение),
  ← (изменить запрос, версии сохраняются), ↻ «Заново» (та же инструкция, новая версия, листание 1/2…),
  ✎ правка, «Вставить». Если в поле мессенджера уже есть текст — «Заменить / Добавить / Отмена».
- Вставка — `textDocumentProxy.insertText`, как у ответа. Без полного доступа сеть клавиатуре
  недоступна — об этом говорит отдельное сообщение до запроса, а не «нет интернета».
- Та же панель (`ReplyComposerView`) в режиме `compose`: чужие для режима элементы скрыты,
  поведение режима ответа не менялось. Тёмная тема — из темы клавиатуры.

## 7. Клавиатура Android

Логический паритет с iOS: ✨ рядом с «+» (тот же адаптивный ряд), `CreatePanel` (заголовок, «Новое»,
✕, поле на 4/3 строки, быстрые добавки, «✨ Написать», результат до 7/4 строк, ←/↻/✎/«Вставить»,
вопрос о непустом поле). Вставка — `InputConnection.commitText` через `HostField`, как у ответа.
В поле пароля «Создать» не открывается. Микрофон в «Создать» не добавлялся (в ТЗ его нет).
Общие кусочки панели (`ActionPill`, `CircleIcon`, `IntentRow`, `ResultRow`, `ConflictRow`) теперь
`internal` и используются обеими панелями — без дублирования.

## 8. Состояния

Один источник истины на каждую сторону, без разрозненных флагов:

- `ComposeSession` (инструкция + `ReplyComposerFlow`) отдельно от `ReplySession` — в ней физически
  нет поля для скопированного сообщения.
- Активная панель вычисляется, а не хранится: `AIFlow { none | reply | compose }` (iOS),
  `isComposing` / `activeFlow` (Android). Открытие «Создать» сбрасывает отложенный ответ,
  выбор персоны закрывает «Создать» — одновременно двух сессий не бывает.
- Стадии: composing → generating → result ↔ editing → conflict; ошибка возвращает туда, откуда
  начинали, с сохранённым запросом. Один запрос за раз (повторные нажатия игнорируются,
  «тикет» отбрасывает поздний ответ после «Стоп»). При скрытии клавиатуры запрос останавливается,
  сессия хранится 10 минут только в памяти; спиннер после перезагрузки клавиатуры не остаётся.
- «Новое» — пустая инструкция, без версий и ошибок. «✕» — всё стирается.

## 9. Локализация

iOS: `ComposeStrings` (ru / kk / en / uz) — язык приложения, а не раскладки, как и остальная клавиатура.
Android: `kb_compose_*` в `values`, `values-ru`, `values-kk`, `values-uz`.
Кнопка настроек: «Пернетақта параметрлерін ашу» / «Открыть настройки клавиатуры» / «Open Keyboard Settings».

## 10. Лимиты

Каждое «Написать» и каждое «Заново» — одна единица той же дневной/месячной квоты, что и ответ
(согласовано). Ошибка провайдера квоту возвращает. Невалидный запрос до провайдера не доходит и квоту
не тратит. Клиенты показывают те же сообщения: «Ответы на сегодня закончились…», «Слишком много запросов…».

## 11. Карточка «Клавиатура» (п. 24)

- **iOS.** Было: «Открыть настройки iOS» + «Настройка клавиатуры» рядом; вторая вела на экран, главная
  кнопка которого — та же «Открыть настройки iOS». Стало: одна основная кнопка
  «Открыть настройки клавиатуры» (`UIApplication.openSettingsURLString` — страница AI Reply в настройках,
  где «Клавиатуры» и «Полный доступ»), и только пока клавиатура не подключена или полный доступ выключен.
  Когда всё готово — две строки статуса без кнопок. Статус перечитывается при возврате из настроек.
  Источник статуса — прежний (клавиатура сама пишет о себе в App Group); частных API нет.
- **Android.** Было: «Открыть настройки клавиатур» + «Настройка клавиатуры». Стало: одно действие по
  ситуации — «Пернетақта параметрлерін ашу», пока клавиатура не включена; «Сменить клавиатуру», пока не
  выбрана; ничего, когда готово (Android сообщает оба состояния надёжно, экран перечитывает их при возврате).
  Пошаговое руководство осталось в Настройках ▸ «Настройка клавиатуры».

## 13. Ограничения и что осталось

1. **Бэкенд не задеплоен** (договорились: деплой делаете вы). Пока на https://ai-reply.kz старая версия,
   «Написать» в приложениях покажет «Сервис сейчас недоступен» (404 → понятная ошибка, а не сбой).
   После деплоя миграция `0006` применится при старте автоматически.
2. **Реальный OpenAI не вызывался**: на этом Mac нет `.env` с ключом, выбрали проверку на моках.
   Промпт проверен тестами (что в него попадает и чего в нём нет); качество текстов на ru/kk/en стоит
   посмотреть после деплоя на паре запросов.
3. Android-экраны приложения (карточка «Клавиатура») не проверены глазами: приложение на эмуляторе
   требует принять оферту и войти; я этого за вас не делал. Проверено сборкой и lint.
4. iOS-статус клавиатуры в Simulator: ad-hoc сборка без entitlements не даёт клавиатуре писать в App Group,
   поэтому состояния карточки подставлялись вручную. На устройстве с подписью это работает как раньше.
5. Не проверено на живых устройствах: реальный WhatsApp/Telegram/Instagram, разные OEM-клавиатуры Android,
   landscape на Android.
6. Длинное поздравление в поле результата Android показывает 7 строк и прокрутку (последняя строка
   выглядывает — это подсказка, что текст длиннее).
