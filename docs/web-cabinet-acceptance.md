# Личный кабинет и AI-профиль — критерии приёмки

Каждый критерий проверяется доказательством (тест, запрос, чтение кода с file:line, скриншот),
а не мнением. Пуш в `main` — только когда все критерии **К1–К7** выполнены (это критические:
утечки, деньги, безопасность, регрессии); **К8–К10** — обязательные, но не блокируют срочный фикс.

## К1. Нет утечек между аккаунтами (критично)
- Аккаунт видит и меняет только свой AI-профиль, свою статистику, своё согласие.
- Cookie-сессия сайта и Bearer-токен приложений не подменяют друг друга; токены приложения
  никогда не попадают в ответы сайта.
- Вкладка, оставшаяся на старом аккаунте, ничего не записывает в новый (`expected_user_id`,
  409 `WEB_ACCOUNT_CHANGED`) — для профиля, согласия и голоса.
- Код передачи из приложения (handoff) одноразовый и короткоживущий; выход с сайта не
  разлогинивает приложения.

## К2. Нет утечек персональных данных (критично)
- Текст AI-профиля, заметки, расшифровки голоса и сами записи не пишутся в логи сервера, в
  `ai_usage_events`, в аудит админки, в URL/query, в ответы об ошибках, в `localStorage` и
  `sessionStorage` браузера.
- Персональные ответы API кабинета отдаются с `Cache-Control: no-store`; страницы кабинета —
  `no-store`, `Referrer-Policy` без утечки адреса.
- Во внешние сервисы уходит только то, что описано в политике: профиль — в OpenAI только внутри
  генерации, запись голоса — в OpenAI только для распознавания и только после согласия.
- Удаление аккаунта удаляет AI-профиль (каскад), политика конфиденциальности соответствует
  реальному поведению на 4 языках.

## К3. Нет уязвимостей веба (критично)
- Каждый изменяющий запрос кабинета требует `Origin` сайта + `X-Requested-With: AIReplyAccount`
  (+ JSON или multipart), cookie `HttpOnly`, `Secure` на https, `SameSite=Lax`, путь `/account/`.
- В скриптах кабинета нет `innerHTML`/`insertAdjacentHTML`/`document.write`/`eval` с данными;
  ссылки из данных проходят проверку протокола; нет открытых редиректов.
- Микрофон разрешён (`Permissions-Policy`) только на `/account` и `/payment`.
- Лимиты: размер тела (JSON 64 КБ, аудио 4 МБ), частота запросов на пользователя/IP.

## К4. Деньги считаются точно (критично)
- Цена ответа = 1 + min(потолок, ⌈(символы − бесплатные)/400⌉); Pro — 1; выключенный профиль — 1.
- Доплата резервируется целиком или не резервируется вовсе; нехватка → ответ без профиля за 1;
  ошибка нейросети → полный возврат; повтор ключа бесплатный и без «бесплатного» профиля.
- Нет отрицательных остатков и двойных списаний при параллельных запросах (`-race`).
- Админка показывает запросы, а не единицы доплаты; настройки списания проверяют диапазоны и
  пишутся в аудит.

## К5. Ничего старого не сломано (критично)
- Старые сборки iOS/Android/macOS/Windows работают без изменений (новые поля ответов только
  добавлены, обязательных полей в запросах не появилось).
- Покупка на сайте (BCC), вход по коду, handoff из приложения, смена аккаунта, `/payment`,
  лендинг, `/mac`, `/windows`, админка — работают как раньше.
- Все Go-тесты (в том числе `-race`) и JS-тесты проходят.

## К6. Промпт безопасен (критично)
- Профиль попадает только в user-сообщение как данные, не может добавить правила, сменить роль
  или язык ответа; блоки запроса (шаблон, инструкция) важнее профиля.
- Скрытые символы (bidi, управляющие) удаляются или отклоняются; лимиты длины соблюдаются.

## К7. Деплой безопасен (критично)
- Миграция `0042` только добавляет (старый бинарник продолжит работать после неё).
- Новых обязательных переменных окружения нет; конфиг-валидация проходит.
- Бэкенд без сайта и сайт без профиля работают (никому не списывается доплата, пока профиль не
  сохранён).

## К8. Адаптивность
- Нет горизонтальной прокрутки и обрезанного текста на 320, 360, 375, 390, 414, 600, 768, 834,
  1024, 1180, 1280, 1440, 1920 px во всех 4 языках; меню, вкладки, панель сохранения, диалог
  согласия и график удобны на телефоне, планшете (обе ориентации) и компьютере.

## К9. Доступность и UX
- Клавиатура (Tab/Enter/Space/стрелки), видимый фокус, подписи у полей, `aria-live` для
  сохранения и записи, корректные состояния загрузки/ошибки/пустых данных, предупреждение о
  несохранённых изменениях, `prefers-reduced-motion`.

## К10. Тексты
- Все строки есть в ru/kk/en/uz, естественные формулировки, одинаковые названия с приложениями
  (Друг/Клиент/Коллега/Партнёр и т. д.), нет английских «хвостов» в других языках.
