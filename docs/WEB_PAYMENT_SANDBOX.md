# Тестовая веб-оплата — 30 октября 2026

Работа ведётся в `Payment`, только для iOS и изолированной среды `/sandbox`.
Новый интерфейс приложения сохраняется. Витрина, цены и новые покупки IAP
убраны из интерфейса; действующий доступ и уже начисленные ответы сохраняются.
Это внутренняя проверка TestFlight, а не подтверждение допуска новой модели
продаж в публичный App Store.

## Путь пользователя

1. Пользователь входит в тестовый аккаунт приложения.
2. По желанию отдельно включает предложения о пакетах и разрешает уведомления iOS.
   Регистрация и системное разрешение сами по себе не включают маркетинг.
3. При готовом тестовом эквайринге и зарегистрированном устройстве сервер ставит
   один `web_topup_offer` на аккаунт. Нужна iOS-сборка не ниже 14.
4. После нажатия приложение запрашивает одноразовый код входа, привязанный к
   текущему аккаунту, и открывает `/sandbox/payment` во внешнем браузере.
   Код действует 60 секунд, хранится на сервере только как хэш и расходуется
   атомарно. Пароль и постоянные токены в URL не передаются.
5. Сайт сразу показывает пакет. Код убирается из адреса до обращения к API.
   Если браузер был открыт под другим аккаунтом, требуется явное подтверждение
   переключения. Просроченная ссылка предлагает повторить вход или войти по почте.
6. Согласованный товар — **30 ответов за 100 ₸**, разово, без автосписаний и срока
   использования. Пользователь отдельно принимает условия веб-покупки и нажимает
   оплату. Цена, состав, получатель и редакция условий фиксируются с заказом.
7. Ввод карты происходит на тестовой странице BCC. Сервер начисляет пакет только
   после аутентифицированного итогового уведомления банка; возврат браузера не
   подтверждает оплату. Повторное уведомление не создаёт повторного начисления.
8. При возвращении в приложение обновляется `/me` и баланс.

Веб-покупка в основном `/payment` не пополняет тестовый `/sandbox`-аккаунт.
Base/Pro и рекуррентные банковские списания этим потоком не продаются.

## Обновление сервера владельцем

Из существующего каталога `ai-reply-back-end` на сервере получить проверенный код
ветки и пересобрать тот же контейнер по порядку из `BACKEND_DEPLOYMENT_CHECKLIST.md`:

```sh
git pull --ff-only origin Payment
docker compose config --quiet
docker compose build backend
docker compose run --rm --no-deps backend -check
docker compose up -d --no-deps backend
```

Новые миграции: `0024` — отдельное согласие на покупку; `0025` — однократность
предложения после очистки истории; `0026` — одноразовые коды веб-входа.
До обновления применяется обычная резервная копия базы по инструкции развёртывания.

## Включение только тестового сценария

Значения ниже владелец задаёт в серверном `.env`, после проверки конфигурации.
Реквизиты и ключи в чат не передаются. Само изменение кода эти переключатели
не включает.

```dotenv
BILLING_SANDBOX_ENABLED=true
BILLING_SANDBOX_BCC_ENABLED=true
BILLING_SANDBOX_PUSH_ENABLED=true
BILLING_SANDBOX_WEB_TOPUP_OFFER_ENABLED=true

# Основной контур остаётся без новой банковской продажи и предложения.
BCC_CHECKOUT_ENABLED=false
WEB_TOPUP_OFFER_PUSH_ENABLED=false
```

Перед `BILLING_SANDBOX_BCC_ENABLED=true` обязательны корректные тестовые реквизиты
BCC и согласованный с банком итоговый callback с отдельным Basic Auth. Описание:
`ai-reply-back-end/docs/BCC_NOTIFY_SETUP.md`. Одних публичных ключей Postman для
подтверждённого начисления недостаточно.

Для тестового push нужны существующие рабочие Firebase/APNs параметры. Явный
переключатель разрешает отправку только по реестру установок отдельной тестовой
базы. Письма-уведомления и отзыв Apple-авторизации из неё остаются выключенными.
Коды входа на почту работают отдельно. Никакой
общей рассылки существующим рабочим пользователям нет.

Если устройство ещё не получило FCM-токен, одноразовое предложение не расходуется:
сервер повторит проверку при регистрации установки. После постановки предложения
в очередь автоматическая повторная реклама не отправляется даже после очистки
истории. Если цена успела измениться до доставки, устаревшее предложение пропускается.

## Проверка после обновления

- `/sandbox/healthz` отвечает успешно; `/sandbox/payment?lang=ru` показывает пакет
  без необходимости предварительного входа.
- В TestFlight указана 1.2.0 (14); аккаунт и API относятся к `/sandbox`.
- Внутри приложения нет витрины покупки и прямой кнопки перехода к эквайрингу.
- Предложение выключено по умолчанию; отказ не мешает использовать бесплатные ответы.
- Нажатие тестового push открывает внешний браузер и нужный аккаунт. Повторное
  использование и просроченный код не дают входа.
- При потерянном ответе создания заказа повтор восстанавливает тот же заказ.
  Истёкшая ссылка сама по себе не означает отказа банка и не создаёт новую оплату.
- После подтверждённой тестовой оплаты начислено ровно 30 ответов; дубликат callback
  не изменяет баланс повторно; другой аккаунт и основной контур не изменяются.

## Ограничения

Реальная доставка push, переход на iPhone и тестовая транзакция BCC требуют
обновлённого сервера и готовой банковской конфигурации. Локальные тесты не заменяют
этот прогон. Условия распространения версии без IAP и с внешними покупками должны
быть отдельно подтверждены для публичного App Store; внутренний TestFlight не
считается таким подтверждением. Диагностика системного звука клавиатуры отложена
по просьбе владельца и в эти изменения не входит.
