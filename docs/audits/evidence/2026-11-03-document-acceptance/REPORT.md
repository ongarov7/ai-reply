Самое опасное (всё ПОДТВЕРЖДЕНО):
1. Цена другого товара вместо нужного (5c): строка «Диван угловой Комфорт» (3550 B) больше бюджета и молча выброшена; единственный отправленный фрагмент — «Чехол на диван угловой; Цена: 24990».
2. Формулы выбрасываются, закупочная цена отправляется (4b, 4d): для «Кофе Арабика 1 кг» модель видит только `Закупка, ₸: 9592`. Внутренние колонки (закупка, поставщик, маржа) уходят в модель.
3. Таблицы DOCX разваливаются на ячейки (9a, 9b): отправлено «Диван угловой «Комфорт»» без цены.
4. Профиль режется до 1000 байт (~575 кириллических символов) раньше всего остального (7a–7d): Services/Policies/Description/Preferences и инструкции из панели молча выпадают; переносы строк схлопываются.
5. Склонения/казахский/транслит/синонимы не находятся (3a, 3d–3h, 1e, 12b): «диваны», «кресла», «диванның», «sofa», «couch», «айфон про» → пусто; «все диваны» нашёл 1 из 8 (совпал предлог «с»).
6. Артикул `A1043` / `A-1043` / кириллическая `А-1043` — нужная строка не попадает или идёт второй (2b, 2d, 2f); слово «Артикул» из шапки совпадает с каждой строкой и забивает все 8 слотов шумом.
7. Кодировки Excel RU/KZ: CSV в Windows-1251 отклоняется общим сообщением; TXT в Windows-1251 и UTF-16LE без BOM «успешно» импортируются иероглифами и молча ничего не дают (8b, 8c, 8i, 8j).
8. Разделитель CSV по первой строке: строка-заголовок прайса или «Цена, ₸» в шапке → деление по запятой, «11 990,50» превращается в «11 990; Column 2: 50;6» (8d, 8e).
9. Сервер отклоняет то, что клиент пропустил (12c): user-промпт 4110 B > 4096 B из-за HTML-экранирования (+320 B); пользователь видит «Что-то пошло не так. Попробуйте ещё раз», Retry шлёт байт-в-байт то же тело и снова падает.
10. Ранжирование: ничья → порядок строк в файле, лишние слова в названии не штрафуются, а в Reply к запросу добавляется пробел (`QuickBarModel.swift:270`) — бонус «весь запрос» получает более длинное название: на сообщение «iPhone 15» точная строка оказалась 5-й (1h).

Безопасность: zip-бомбы, >2048 записей, billion laughs, XXE, битые/переименованные архивы — отклоняются за ≤ 1,9 с и ≤ 64 МБ RSS; локальный файл через XXE не прочитан. Проверка `<!DOCTYPE` обходится кодировкой UTF-7 (документ с DTD импортирован), но XMLParser всё равно не раскрывает сущности — это потеря только эшелона защиты.

## 1. Метод и воспроизведение

Клиент (Swift): отдельный пакет `harness/` зависит от реального `AirReplyKit` по локальному пути (`.package(path: ".../AirReply-macOS/Packages/AirReplyKit")`); исходники продукта не копировались, `@testable` не понадобился. Путь целиком реальным кодом: файл → `QuickBarModel.importDocument(url)` (реальный `DocumentContextImporter().parse(url:)`) → `QuickBarModel.submit()` или `panelDidOpen(copied:)`+`reply(to: .client)` (реальное построение запроса и `ContextSnapshot.resolve()` → `ContextRetriever.context`) → перехват на границе `Generating` → повтор того же вызова через реальные `ServerGenerator` + `APIClient` → перехват точного JSON-тела на границе `HTTPTransport`. Подделаны только системные границы (как в `Tests/AirReplyUITests/QuickBarModelTests.swift`): `/config` с `mac_context_generation=true` и лимитами 400/400, буфер обмена, микрофон, транспорт. ## 2. Как устроен путь

| Шаг | Где | Что происходит |
|---|---|---|
| Импорт | `DocumentContextImporter.swift:57-89` | xlsx/csv: строка таблицы = сегмент `"Заголовок: значение; …"`, раздел `"<лист>, row N"`; txt/docx/pdf: одна строка текста = сегмент (`:105`), длинные режутся по 1200 символов |
| Запрос | `QuickBarModel.swift:253` / `:270` | Message: вся инструкция; Reply: всё скопированное сообщение + " " + инструкция (пробел остаётся без инструкции) |
| Профиль | `QuickBarModel.swift:405-408` | выбранный профиль (или пустой) + временные вложения; инструкции панели дописываются в конец `instructions` (поле Preferences) |
| Ранжирование | `ContextProfiles.swift:229-257` | токены = сплит по не-буквенно-цифровым (`:279`), регистр/диакритика свёрнуты; очки = Σ min(12, длина совпавшего токена) + 30 если сегмент содержит весь запрос + 30 если любую пару соседних слов; ничья → порядок в файле |
| Отбор | `ContextProfiles.swift:258-268` | порог max(1, лучший/2); первые 8 по рангу; строка длиннее остатка пропускается целиком |
| Бюджет | `ContextProfiles.swift:226-228` | `availableBytes = 3072 − UTF-8 байт запроса`; профиль первым, до min(1000, available) байт; ссылки — в остаток |
| Метка | `ContextProfiles.swift:251-252` | `"[<имя файла> · <раздел>]\n<текст>"` |
| Клиентская проверка | `Generator.swift:180-187` | профиль ≤ 1500 скаляров, ≤ 8 ссылок, ссылки ≤ 4000 скаляров, всё ≤ 4096 B |
| Сервер | `mac_context.go:49-68`, `:85-108` | те же поля + весь user-промпт (обёртки + сообщение + инструкция + `html.EscapeString(контекст)`) ≤ 4096 байт |

Пример точного тела (1a, POST /api/v1/ai/compose, 1423 B): `{"template_id":"client", … "context":{"references":["[catalog.xlsx · Прайс, row 4]\nАртикул: A-1003; Наименование: iPhone 15 Pro Max; Цена, ₸: 699990; Остаток, шт: 2; Категория: Смартфоны", …]},"instruction":"Сколько стоит iPhone 15 Pro?", … "output_char_limit":400}`. Модель получает (10a): `<context_reference>\n[injection.csv · CSV, row 3]\nНаименование: Акция; …\n</context_reference>` плюс блок REFERENCE DATA в developer-промпте (`mac_context.go:81-83`). Полные промпты по кейсам — в каталоге work/out/server.

## 4. Бюджет: клиент против сервера

| Ограничение | Клиент | Сервер |
|---|---|---|
| Профиль | ≤ 1500 скаляров и затем ≤ min(1000, available) байт (`ContextProfiles.swift:227-228`) | ≤ 1500 рун (`mac_context.go:49`) |
| Ссылки | ≤ 8, ≤ остатка байт; validate ≤ 4000 скаляров | ≤ 8, ≤ 4000 рун |
| Профиль+ссылки | ≤ 3072 − байт запроса; validate ≤ 4096 B | ≤ 4096 B сырых |
| Весь user-промпт | не моделируется | ≤ MAC_CONTEXT_INPUT_TOKEN_BUDGET (4096; допустимо 256–8192) после `html.EscapeString` и обёрток (`:92-107`) |

Измерено реальным кодом:
- Кириллица: 1,5–2,0 B на символ (1a: 797 симв./1169 B; профиль 7a: 575/992), `₸` = 3 B. «1000» для профиля ≈ 575 русских символов, а не 1500 разрешённых сервером; при максимальном запросе (Reply 400 + инструкция 400 = 1432 B, 7d) на ссылки остаётся 648 B ≈ 4 строки.
- Клиент никогда не приближается к посимвольным лимитам сервера, но оставляет на обёртки только 1024 B + байты запроса. Фиксированный текст: compose ≈ 115 B + инструкция, reply ≈ 389 B + сообщение + инструкция; теги 39 B (профиль) и 43 B на ссылку (до 383 B). При заполненном бюджете предел: compose ≈ 3570 B + рост, reply с инструкцией ≈ 3843 B + рост. `"`, `'`, `&` дают +4 B, `<`/`>` +3 B: ~64 кавычки/амперсанда в reply-контексте → отказ. 12a: +320 B, запас 17 B; 12c: отказ.
- Сервер публикует `mac_context_limits` в /config (`me_handlers.go:279`), клиент их не читает (`Models.swift:292-309`). При снижении бюджета оператором отказ получили бы: при 3072 — 7d, 12a, 12c; при 2048 — 7b, 7c, 7d, 12a, 12c.
- `field = "context"` → `GenerationError.server` (`Generator.swift:56-64`) → `issue.server` (`QuickBarView.swift:494`).

## 7. ПОДОЗРЕНИЯ (только код)
- `html.EscapeString` превращает кавычки в `&#34;` и т. п. (видно в `out/server/12a.user.txt`); при правиле «Preserve supplied names and numbers exactly» модель может повторить сущности в ответе. `mac_context.go:92,96`.
- Свёртка с `locale: .current` (`ContextProfiles.swift:230, 236, 241, 278`) делает токенизацию зависимой от локали; для RU/KK практически безвредно.
- Вложенные абзацы DOCX (текстовые поля) обнуляют внешний абзац (`DocumentContextImporter.swift:249`).
- Несколько крупных вложений в профиле упрутся в лимит кэша 32 МБ (`ContextProfiles.swift:149, 175`) с тем же общим текстом ошибки.
- Лимит 2048 записей отклонит прайсы с множеством встроенных фото (такие файлы обычно и так > 8 МБ).

## 8. Что работает (подтверждено)
CSV с BOM/`;`/многострочными ячейками/десятичной запятой (8a); TXT UTF-16 с BOM (8g, 8h); одноколоночная PDF-таблица (9f); общие/встроенные строки XLSX, разреженные ячейки, несколько листов (5b); точные запросы с полным названием (1f, 1g, 3b) и точным артикулом (2a, 2e); потоковые ZIP с дескриптором; враждебные входы отклоняются быстро и с ограниченной памятью; XXE не читает файлы; закрывающий тег в документе не ломает обёртку; клиентский контекст ни разу не превысил посимвольные лимиты сервера.
