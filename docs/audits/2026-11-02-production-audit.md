# Аудит перед запуском — 02.11.2026

Ветка `main`, коммиты `7a90b5a..7586037` (20 штук, все в origin). Реальные платежи и боевые данные не трогались.

## 1. Найдено и исправлено

**Оплата на сайте через BCC (desktop)**
- Брошенная или отклонённая первая оплата подписки навсегда блокировала покупку подписки. Теперь через 30 минут (отказ — сразу) старый мандат закрывается.
- Повторная подписка во время уже оплаченного периода покупала те же дни второй раз. Теперь новый период начинается после оплаченного.
- Одобрение после записанного отказа по тому же заказу получало 503 без следа: деньги списаны, доступа нет. Теперь начисляется, приходит алерт.
- Возврат подписки шёл без RECUR_REF, который банк требует для рекуррентной цепочки. Добавлен. Повтор возврата разрешён только после явного отказа (ACTION=2). Ответ ACTION=3 повторно не отправляется: так нет риска двойного возврата.
- Продление без ответа банка висело вечно. Прямой отказ на запрос 171 игнорировался. Теперь отказ записывается, а через 24 часа без исхода заказ уходит в needs_review с алертом.
- Тихие сбои стали видны: отклонённые уведомления банка, отказы карт, неподтверждённые продления и возвраты, неотправленные чеки.
- Брошенный заказ держал страницу оплаты в «ожидании». Через 30 минут он показывается как истёкший; поздняя оплата всё равно начисляется.
- Возврат браузера из банка через GET давал 405. Теперь принимается.

**App Store (iOS)**
- Production отклонял Sandbox-покупки App Review, а это почти гарантированный отказ ревью. Теперь Sandbox разрешён только аккаунтам из APPLE_IAP_SANDBOX_ACCOUNTS (по умолчанию REVIEW_LOGIN_EMAIL), запись помечается как Sandbox и в выручку не идёт.
- Сбой базы при проверке аккаунта выглядел как «покупка чужого аккаунта». Теперь это 503 и автоматический повтор, как и для Google Play.

**Безопасность и стабильность**
- Потерянный ответ при обновлении токена разлогинивал пользователя на iOS, Android и macOS. Теперь повтор в течение 60 секунд принимается. Android сохраняет новый токен даже при отмене запроса.
- `/auth/refresh` и `/config` сидели в общем лимите 60 в минуту на IP. За NAT мобильных операторов это разлогинивало целые группы людей. Теперь у них отдельный широкий лимит.
- Возврат денег мог сделать любой админ. Теперь только роль admin; в аудит пишутся сумма, валюта и статус.
- Docker: логи без ротации могли заполнить диск, после чего SQLite перестаёт писать. Деплой убивал сервер через 10 секунд. Теперь ротация 50 МБ × 5 и 30 секунд на остановку.

**Приложения**
- macOS: после оплаты на сайте оставалась карточка «ответы закончились». «Тарифы» открывали сайт без привязки к аккаунту, и оплата могла уйти на другой аккаунт. Исправлено, теперь используется одноразовая ссылка входа.
- Android: Pro показывался как «доступно 0». Прогресс-бар 0/0 падал при включённом TalkBack. Исправлено.
- iOS, Android, macOS: краши прошлых запусков отправляются на сервер (MetricKit, обработчик исключений) и приходят в Telegram.

**Секреты.** Репозиторий публичный. В текущих файлах и во всей истории git реальных секретов нет. Есть публичный тестовый ключ BCC: его публикует банк, в production сервер его не принимает. Есть клиентские Firebase-ключи: это не секрет, но их нужно ограничить.

## 2. Telegram-алерты

| Уровень | Когда |
|---|---|
| CRITICAL | паника в API или воркере, падение при старте, база не читается или писатель завис, на диске меньше 500 МБ, краш приложения у вошедшего пользователя |
| ERROR | любая ошибка уровня Error, ответ HTTP 500, отклонённое уведомление банка, неизвестный исход продления или возврата, отказ возврата, неотправленные чеки, ошибка покупки в приложении |
| WARNING | отказ карты, OpenAI таймаут/429/5xx (без отмен клиентом), сбой отправки кода на почту, сломанный push (APNs, ключ, проект), предупреждения конфигурации при старте, TRUST_PROXY=false за прокси, на диске меньше 2 ГБ, остановка сервера |
| RECOVERED | сервер запущен, база или диск восстановились |

Доставка асинхронная и не тормозит запросы. Одинаковые алерты за 5 минут склеиваются, потом приходит число повторов. Лимит 20 сообщений в минуту. Токен бота хранится только на сервере. Почта, токены, длинные номера и ссылки вычищаются.

## 4. Что нужно сделать до запуска (владелец)

1. Задеплоить backend (новых миграций нет). Затем выполнить `server -check` и `server -alert-test`.
2. В production .env поставить `TRUST_PROXY=true`: сервер стоит за Caddy.
3. Заполнить три переменные Telegram (раздел 5).
4. На время ревью держать заполненными REVIEW_LOGIN_EMAIL и REVIEW_LOGIN_CODE. Ревьюер входит по почте, не через Apple.
5. BCC: подтвердить в банке боевой NOTIFY_URL (POST и Basic Auth). Ограничить в Caddy IP-адреса банка. Если боевой MAC-ключ собирали на xor.pw, запросить новые компоненты.
6. В Google Cloud ограничить Firebase API-ключи: для Android пакет и SHA-1, для iOS bundle id.
7. Заказы в needs_review решаются вручную по кабинету BCC: инструмента в админке нет. Если человек заплатил дважды, возвращать более поздний заказ.
8. Решить вопрос со старыми бесплатными аккаунтами: после миграции 0022 у них 0 ответов в день.

## 6. Остались (P2, не блокеры)

- Чужие неверные коды могут на 24 часа заблокировать вход по почте конкретному адресу.
- Удаление аккаунта с сайта защищено 4-значным кодом.
- Анонимные установки и частые обновления токена раздувают таблицы.
- `synchronous=NORMAL`: при падении ВМ можно потерять последние секунды записей. Сначала замерить fsync на VPS.
- iOS продаёт Apple-подписку аккаунту, у которого уже есть подписка BCC.
- Две копии macOS-приложения делят одну сессию.
- Android расшифровывает Keystore на главном потоке клавиатуры.
- Закончившийся баланс OpenAI выглядит как обычный 429.
- Windows-приложения в репозитории нет, есть только архитектурные заметки.
