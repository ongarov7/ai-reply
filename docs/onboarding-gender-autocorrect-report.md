# AI Reply — онбординг v2, род отправителя, автокоррекция, качество ответов (05.10.2026)

Итоговый инженерный отчёт по ТЗ «onboarding / keyboard setup / grammatical gender / autocorrect /
AI quality». Коммиты — в `main` поверх `43ac4d4` (TestFlight build 4).

**Порядок выката:** сначала бэкенд (миграции `0009`, `0010` применяются при старте), потом
приложения. Новые клиенты отправляют новые поля только если сервер объявил их в
`GET /api/v1/config → features`, поэтому новые сборки работают и со старым сервером, а старые
сборки — с новым.

---

## A. Что было в проекте (аудит)

- **Бэкенд** (Go, SQLite): промпт собирается только на сервере (`internal/ai`), клиентские
  `ReplyPromptBuilder` в проде не используются. Запросы декодируются с `DisallowUnknownFields` —
  любое новое поле требует флага в `/config`. Квота резервируется до вызова модели и
  возвращается при ошибке. Текст сообщений нигде не хранится и не логируется (это проверяют тесты).
- **iOS**: приложение + клавиатура (extension), общий код в `Shared/`, App Group
  `group.kz.ai-reply.shared`. Проект — явные ссылки на файлы (xcodegen на этом Mac нет).
  Клавиатура читает буфер только по нажатию персоны/«Вставить». Детект «клавиатура включена» —
  по сердцебиению в App Group (работает только с Full Access).
- **Android**: приложение + IME в одном процессе, ручной DI, SharedPreferences. IME не
  использовала composing text вообще. **Android не отправлял профиль в запросе** — правки профиля
  после регистрации не доходили до ответов (исправлено).
- Онбординг был: bool `hasCompletedOnboarding`, 4 шага, без версии; автокоррекции, рода,
  аналитики на клиентах не было.

## C. Бэкенд

- **Миграции (только добавление):**
  - `0009`: `user_profiles.grammatical_gender` (по умолчанию `unspecified`),
    `onboarding_version` (1 для тех, кто прошёл старый онбординг), `ai_usage_events.prompt_version`;
  - `0010`: таблица `product_events`.

  Откат: старый бинарник игнорирует новые колонки.
- **`PATCH/POST /me`:** `grammatical_gender` (неверное значение → 400), `onboarding_version`
  (0–1000, хранится максимум).
- **`/ai/reply`:** `profile.grammatical_gender`, `input_language`.
- **`/ai/compose`:** `profile.grammatical_gender`, `input_language`; хендлер теперь читает профиль из БД.
- **`POST /api/v1/ai/polish`:**
  - свой лимит 20/мин, дневную квоту не тратит;
  - детерминированная защита: числа, имена, ссылки, @/#, цитаты, длина, язык;
  - выключается `AI_POLISH_ENABLED`.
- **`POST /api/v1/analytics/events`:**
  - строгий allowlist имён, ключей и значений, свободный текст невозможен;
  - свой лимит;
  - `PRODUCT_EVENTS_ENABLED`.
- **`/config features`:** `sender_profile`, `instruction_polish`, `product_events`.
- **Логи:** `ai_reply_generated` / `ai_reply_failed` / `ai_reply_repaired` с `prompt_version`, без
  текста и без рода. `OPENAI_TEMPERATURE=none` убирает температуру (для reasoning-моделей);
  пустое значение по-прежнему 0.7.

## D. iOS

**Приложение**
- **Онбординг v2.** Шаги: приветствие → род → клавиатура → Full Access → «скопируй и ответь» → практика.
  - Версия устройства (`completedOnboardingVersion`, текущая — 2); после перезапуска продолжает с того же шага.
  - «Как пользоваться AI Reply» в Настройках открывает обучение, ничего не сбрасывая.
- **`KeyboardStatusMonitor`:** Darwin-уведомление от клавиатуры плюс сердцебиение, обновление раз в секунду
  на шагах клавиатуры, поле «Попробуйте здесь».
- **Род.**
  - Выбор в онбординге и в Профиле.
  - Синхронизация через `PATCH /me` (с номером ревизии и повтором).
  - Выбор male/female с сервера подхватывается до онбординга, поэтому на новом устройстве вопрос не повторяется.
- **Настройки:**
  - статус клавиатуры и Full Access;
  - переключатель «Умная коррекция» (по умолчанию включён);
  - атрибуция словарей.

**Клавиатура**
- Строка подсказок стоит на месте чипов персон и показывается только во время набора слова. Высота не меняется.
- Автоисправление на пробеле и пунктуации, отмена — backspace сразу после исправления.
- Не срабатывает посреди слова. Перед правкой заново читает текст поля.
- `UITextChecker` проверяет ru/en, `UILexicon` подставляет замены текста и имена контактов.
- Отключается в полях URL, e-mail, пароль, OTP и в полях с `autocorrectionType = .no`.
- Полировка инструкции работает так же, как на Android (см. раздел E).
- Reply без Full Access показывает понятное сообщение вместо «нет сети».
- **Ряд персон (по замечанию заказчика):** `[✨][Друг][Клиент][Бизнес][Работа]`, кнопка «+» удалена.

## E. Android

**Приложение**
- **Онбординг v2.**
  - Те же шаги, без Full Access.
  - Версия и шаг хранятся в `aireply_device`, этот файл исключён из бэкапа.
  - Статус IME обновляется при возврате фокуса и через `ContentObserver`, поэтому выбор в системном пикере сразу виден.
- **Запрос ответа теперь несёт блок профиля:**
  - описание, роль, тон, бизнес — при `reply_preferences`;
  - род и `input_language` — при `sender_profile`.

  Флаги запросов по умолчанию выключены.
- Буфер обмена: принимаются и HTML-клипы. «Чувствительные» клипы (Android 13+) по-прежнему отклоняются.

**IME**
- Полноценный composing-процесс:
  - текущее слово — `setComposingText`, на разделителе — `commitText`/`finishComposingText`;
  - перед любой операцией с полем composing завершается;
  - внешнее перемещение курсора отслеживается через `onUpdateSelection`.
- Отмена исправления — backspace сразу после него.
- Пробел после выбранной подсказки убирается перед пунктуацией («слово,»).
- Отключение по типу поля (пароли, `NO_SUGGESTIONS`, e-mail/URI, нетекстовые поля) возвращает прежнее поведение: обычный `commitText`.
- **Полировка:** через 1,4 с паузы в поле инструкции появляется предложение «✨ …» с «Отменить» на 5 с.
  - Только для поля инструкции.
  - Только при включённой коррекции и флаге сервера.
- **Ряд персон:** `[✨][Друг][Клиент][Бизнес][Работа]`, кнопка «+» удалена.
- **Микрофон в панели ✨:** см. раздел L.

## F. Качество ответов ИИ

- **Одна иерархия промпта.**
  - Developer-часть: ROLE → PRODUCT RULES → LANGUAGE → SENDER → STYLE → OUTPUT. Пишет только сервер, из перечислений.
  - User-часть: данные в блоках `<incoming_message>`, `<user_instruction>` и др. Скопированный текст — данные, не команды.
- **Правила языков:**
  - русский: живой порядок слов, без канцелярита («иметь возможность», «являться»), без
    лишних «я», не больше одного «!»;
  - казахский: сказуемое в конце, сингармонизм, сен/Сіз, настоящие буквы ә ғ қ ң ө ұ ү һ і, без калек;
  - английский: сокращения, без шаблонных фраз.
- **Намерение пользователя:** отказ остаётся отказом, время и цена берутся точно, факты не выдумываются.
- **Длина:** по длине входящего сообщения, без вступлений «Конечно! Вот вариант:».
- **Детерминированная проверка после модели:**
  - очистка от меток и кавычек;
  - ошибка рода (русский);
  - не тот язык;
  - мета-текст.

  Один ремонт-вызов делается только при найденной проблеме; квота списывается один раз.
- Версии промптов: `reply_v2`, `compose_v2`, `polish_v1`, `repair_v1`. Версия пишется в `ai_usage_events`.
- **Набор оценки** `internal/ai/eval`: 50 кейсов (RU/KK/EN, мужской, женский и неуказанный род,
  отказ и согласие, примеры A–E из ТЗ, латиница, транслит). Проверяются свойства, а не
  точные фразы. Оффлайн-тесты доказывают, что каждая проверка ловит плохой пример. Живой прогон:
  `AIREPLY_LIVE_EVAL=1 OPENAI_API_KEY=… go test ./internal/ai/eval -run TestLiveEval -v`.

**Язык ответа (требование заказчика):** язык ответа = язык скопированного сообщения.
- Язык телефона, приложения, раскладки и текст инструкции или быстрых кнопок («Say that I agree») его не меняют.
- Меняют только явная просьба в инструкции («ответь на русском», «на англ», «qazaqsha») и ручная настройка языка в профиле.
- Сервер называет язык и проверяет его только при высокоточном определении. В сомнительных
  случаях (транслит, одно слово, эмодзи) модель просто отвечает на языке сообщения, без принудительного ремонта.
- Распознаются казахский без казахских букв («Калайсын?», «Рахмет»), казахская латиница
  («Salem! Qalaisyn?»), смешанный RU/KK.
- Если инструкция написана на другом языке, в промпт добавляется:
  «Note: <user_instruction> is written in Russian, but the reply must be in Kazakh.»

## G. Как род доходит до генерации

`UserProfile.grammaticalGender` хранится локально. При изменении он уходит на сервер через `PATCH /me`
(при `sender_profile`) и дополнительно передаётся в каждом запросе в `profile.grammatical_gender`.

Сервер выбирает так:
1. валидное значение из запроса;
2. значение из БД;
3. иначе `unspecified`.

Значение — перечисление, поэтому секцию SENDER в developer-промпте пишет сервер. Что в ней:
- для мужчины и женщины: требование нужных форм в русском;
- для `unspecified`: нейтральные конструкции («Приятно слышать», «С удовольствием»);
- для казахского и английского: ничего не добавлять.

Если в русском ответе нашлась форма не того рода, делается один ремонт. Род никогда не выводится из имени, почты или аккаунта.

## H. Автокоррекция

**Данные.**
- **Источник.** Частотные словари Leipzig Corpora (CC BY), по 50–80 тыс. слов и 110–390 тыс. известных форм (фильтр Блума). Около 4 МБ на платформу.
- **Чистка.**
  - Чёрный список корпусных опечаток.
  - Казахские слова в «простом» написании.
  - Оскорбительные слова не предлагаются.

**Алгоритм** одинаковый на Swift и Kotlin; 77 строк общей таблицы `autocorrect_parity.json`
проверяются на обеих платформах, расхождений 0 на 7031 сгенерированных случаях.
- Взвешенное расстояние (соседние клавиши, перестановки, двойные буквы).
- Казахские пары (к→қ дешевле, қ→к запрещено).
- е/ё.
- Порог автозамены и запас до второго кандидата.
- Таблица английских сокращений (`dont` → `don't`, `i` → `I`).
- Казахская подсказка для слов без казахских букв («кайда» → «қайда»), не на русских словах.

**Защита:**
- не исправляются ссылки, почта, @/#, числа, КАПС, iPhone-подобные слова, смешанное письмо;
- выученные слова: локально, до 500 на язык, не синхронизируются.

**Скорость:**
- около 2 мс на слово в release, около 20 мс в Debug;
- загрузка лениво, вне главного потока, ввод никогда не ждёт.

**Уровень 2 — полировка:**
- только поле инструкции в нашей панели;
- предложение показывается после паузы, пользователь принимает или отклоняет;
- текст в других приложениях никуда не отправляется.

## I. Онбординг и буфер обмена

- **iOS**
  - Есть кнопка «Открыть настройки клавиатуры» в прежнем дизайне (страница приложения в Настройках) и альтернативный путь через «Основные ▸ Клавиатура ▸ Клавиатуры».

  - Про «Разрешить вставку» сказано с оговоркой о версии iOS.
  - Буфер читается только по нажатию, без опроса. Пустой буфер даёт сообщение «Скопируйте сообщение».
- **Android**
  - Используется системный поток: настройки способов ввода и `showInputMethodPicker`.
  - Статус («Включена» / «Выбрана») обновляется сам. Полного доступа на Android нет.
  - Буфер читается только активной IME по нажатию. Уведомление Android о чтении буфера объяснено.

## K. Ограничения ОС (не баги)

- **iOS:**
  - приложение не может узнать, включена ли его клавиатура: статус зелёный после первого открытия клавиатуры;
  - без Full Access у клавиатуры нет сети, буфера и вибрации, и она может не видеть настроек приложения;
  - **у клавиатуры нет доступа к микрофону** (запрет Apple), поэтому голосовой ввод в панель ✨ на iOS невозможен;
  - в защищённых полях (пароли) iOS показывает системную клавиатуру;
  - запрос «Разрешить вставку» показывает сама iOS.
- **Android:**
  - IME не может сама запросить разрешение (используется прозрачная Activity);
  - распознавание казахского зависит от голосового сервиса телефона;
  - на некоторых OEM-прошивках поведение composing-текста в WebView отличается.
- Обе платформы: часть приложений запрещает сторонние клавиатуры в отдельных полях.

## L. Микрофон в панели ✨ и «Ответить на скопированное»

**Android — микрофон в панели ✨ («Создать»):**
- **Тот же голосовой модуль, что в панели ответа.**
  - Сначала распознаватель на устройстве, при неудаче системный.
  - Разрешение через прозрачную Activity.
  - Лимит записи 60 с.
  - Микрофон освобождается при скрытии клавиатуры.
- **Кнопка та же**, нижний ряд: подсказки + 🎙 + «Написать».
- **Строка статуса фиксированной высоты**, поэтому панель не прыгает при записи.
- **Язык распознавания — по текущей раскладке** в обеих панелях: ҚАЗ → kk-KZ, РУС → ru-RU, ENG → en-US.
  Если язык не установлен на устройстве, пробуется системный распознаватель. Если и он не умеет,
  показывается понятное сообщение.
- **Вставка текста:**
  - в место курсора, с нужным пробелом и заглавной буквой в начале предложения;
  - только целыми словами в пределах лимита;
  - ничего не отправляется автоматически.
- **Корректно обрабатываются:** повторное нажатие (стоп), «Написать» во время записи, скрытие или смена
  поля, смена раскладки, открытие персоны, отказ в разрешении, нет сети, «ничего не распознано»,
  распознаватель занят, звонок.
- **Тесты:** 59 новых JVM-тестов. На эмуляторе проверены состояния и разрешения. Распознавание живой
  речи на эмуляторе не проверить (нет звука), его нужно проверить на телефоне.

**Обе платформы — «Ответить на скопированное» в панели ✨:**
- **Где кнопка:** отдельной строкой под полем запроса.
- **Что делает нажатие:**
  - читает скопированное сообщение (на iOS нужен Full Access);
  - переводит панель в обычный ответ: исходное сообщение, последняя персона (или «Друг»), набранный или надиктованный запрос.
- **Генерация** — только по «Ответить».
- **Пустой буфер** даёт сообщение «Скопируйте сообщение», панель остаётся.

**iOS:** микрофона в клавиатуре нет — запрет Apple для сторонних клавиатур (раздел K).
