# Голосовой ввод в Android-клавиатуре (gpt-transcribe) и цифровые клавиатуры

Дата: 2026-10-14. Только Android и бэкенд, iOS не менялся.

## 1. Почему микрофон «обрывался»

Раньше клавиатура использовала системный `SpeechRecognizer` (`AndroidSpeechRecognitionClient`).

Google-распознаватель сам закрывает сегмент после паузы в речи: `onEndOfSpeech`, затем `onResults`. Клиент считал это концом диктовки (`Done`). Поэтому любая пауза «подумать» завершала запись.

Параметры тишины (`EXTRA_SPEECH_INPUT_*_SILENCE_LENGTH_MILLIS`) Google игнорирует, так что увеличение таймаута ничего бы не дало.

## 2. Новая схема

Микрофон клавиатуры:
1. Запись на телефоне (`AudioRecord`, 16 кГц моно).
2. Пауза, продолжение, Готово.
3. Один файл M4A/AAC (около 32 кбит/с, 40 с ≈ 160 КБ).
4. `POST /api/v1/ai/transcribe` на нашем сервере.
5. OpenAI `gpt-transcribe` (`/v1/audio/transcriptions`, `languages[]`, `prompt`).
6. Текст.
7. Пользователь проверяет и правит.
8. Reply/Write — только по нажатию.

Тишина больше ничего не завершает: запись идёт, пока её не остановят пауза, «Готово», «Отмена» или лимит.

## 3. Лимит 40 секунд

- **Время берётся из записанного звука:** учитываются сэмплы, а не таймер. Пауза, открытие микрофона и загрузка время не тратят.
- **Жёсткий потолок в самом рекордере:** ровно 40 000 мс. Лишний кусок обрезается, микрофон закрывается, и только потом приходит `onLimitReached`.
- **Предупреждения:** на 30 с «осталось 10 с», на 35 с «осталось 5 с» (красным). Лёгкая вибрация срабатывает, если включена вибрация клавиш.
- **На 40 с** запись автоматически отправляется на распознавание, как при «Готово». Ответ ИИ никогда не запускается сам.
- **Проверено на эмуляторе:**
  - пауза на 25 680 мс после 25,7 с записи;
  - продолжение;
  - лимит ровно на 40 000 мс.

## 4. Состояния (`DictationController`)

| Состояние | Что значит |
|---|---|
| `IDLE` | Записи нет. |
| `STARTING` | Микрофон открывается (в фоновом потоке). Время не идёт. |
| `RECORDING` | Идёт запись. Тратится только здесь. |
| `PAUSED` | Микрофон закрыт (индикатор Android гаснет). Звук и остаток времени сохраняются. |
| `FINALIZING` | Собирается один файл. |
| `TRANSCRIBING` | Запрос на сервере. «Отмена» работает. |
| `RECOVERING` | Сеть пропала. Один автоповтор с тем же `request_id`. |
| `REVIEWING` | Текст в инструкции, есть «Убрать», или текст ждёт «Вставить» для поля приложения. |
| `ERROR` | Ошибка. Звук сохранён для «Повторить». |
| `CANCELED` | Конечное состояние сессии. Все поздние колбэки игнорируются. |

Что делает каждая кнопка:
- **«Пауза»:** закрывает микрофон.
- **«Продолжить»:** открывает микрофон с оставшимся временем. После лимита недоступно.
- **«Готово»:** закрывает файл и отправляет его.
- **«Отмена»:**
  - сразу закрывает микрофон;
  - обрывает запрос (сокет закрывается сразу, `ApiClient`);
  - удаляет звук;
  - поле остаётся как было.

Если начать печатать во время записи, запись встаёт на паузу. Пауза срабатывает до щелчка клавиши, чтобы он не попал в звук.

## 5. Две точки входа

1. **🎙 в ряду персон, справа, зеркально к ✨ (обычный голосовой ввод).**
   - Записанное вставляется в поле приложения у курсора, с пробелами и заглавной буквой.
   - ИИ не вызывается.
   - Не показывается:
     - в полях паролей, номеров, адресов и в полях без класса ввода;
     - если приложение передало `nm` или `noMicrophoneKey`.
   - Текст вставляется сам только в ту же самую сессию ввода, а не просто в поле с тем же id: в WebView и Compose id у всех полей одинаковый.
   - Если активно другое поле того же приложения, запись ставится на паузу, а текст ждёт явного «Вставить».
   - В другом приложении запись сбрасывается.
2. **Микрофон в панели ответа (рядом с Reply) и в ✨ Create (рядом с Write).**
   - Распознанная инструкция попадает в поле инструкции.
   - Видны «Добавлено голосом», кнопка «Убрать» и счётчик `54 / 400`.
   - Reply/Write пользователь нажимает сам.

## 6. Лимит символов

- **Источник:** `/api/v1/config` → `max_instruction_length`. Его меняет админка (`system_settings`), по умолчанию 400. Считаются кодовые точки, как на сервере.
- **Голосовой текст никогда не обрезается.** Если он длиннее лимита:
  - текст остаётся целиком;
  - строка пишет «слишком длинно»;
  - Reply/Write заблокированы, пока пользователь не сократит.
- **Быстрые фразы (интенты) больше не режут текст.** Раньше `applyIntent` обрезал всё по лимиту.
- **Reply раньше молча обрезал** длинную инструкцию (`AIReplyService` и сервер). Теперь отправка просто не начинается.

## 7. Сервер

Эндпоинт `POST /api/v1/ai/transcribe` (multipart):
- **Поля:** `audio`, `duration_ms`, `languages`, `request_id`, `purpose`.
- **Доступ:** `requireUser` + `requireConsent`, затем лимит в минуту и в сутки.
- **Проверки:**
  - формат определяется по байтам (M4A/WAV);
  - длительность читается из контейнера, максимум 41 с;
  - 4 МиБ;
  - всё в памяти, без файлов на диске и без хранения.
- **Повтор того же `request_id`** берётся из кэша на 10 минут, второй раз в OpenAI не идёт.
- **Кредиты на ответы не тратятся.** Транскрипция учитывается отдельно (`ai_usage_events`, mode `transcribe`).
- **В `/config`** добавлен `features.voice_transcription`. Без него микрофоны в клавиатуре скрыты.
- **Переменные окружения:**

| Переменная | Значение |
|---|---|
| `OPENAI_TRANSCRIBE_MODEL` | `gpt-transcribe` |
| `TRANSCRIBE_ENABLED` | `true` |
| `LIMIT_TRANSCRIBE_PER_DAY` | `100` |
| `RATE_TRANSCRIBE_PER_MINUTE` | `10` |

**Важно:** сначала задеплоить бэкенд, потом выпускать приложение. Пока сервер не прислал флаг, микрофонов не будет.

## 8. Цифры и символы

- **Отдельные клавиатуры для полей:**
  - телефон: 1–9, `* 0 #`, `+ ( ) -`;
  - число: `-` и `.`/`,` только если поле это разрешает;
  - дата: `. / : -`.
- **Правая колонка:** ABC, пробел, ⌫, действие.
- **Высота та же:** клавиатура не «прыгает».
- **Ряд цифр над буквами в полях паролей** (EN/RU) — только там, где он помещается без уменьшения клавиш.
- **На странице `=\<` появились `<` и `>`.**
- **В числовых полях:** двойной пробел больше не ставит точку, а пробел не выкидывает с цифровой клавиатуры.

## 10. Что не проверено и что осталось

- **Реальный телефон:** не проверено.
  - звук и задержки на разных устройствах (Samsung, Xiaomi);
  - звонок во время записи;
  - Android 8–9 (OMX-кодек).
- **Настоящий `gpt-transcribe`:** ключа OpenAI на этом Mac нет, поэтому проверено только с моком.
  - Нужна проверка на записях носителей: казахский, русский, английский, смешанная речь.
  - Проверить, что `languages[]=kk` принимается. Если нет, сервер один раз повторит запрос без подсказок.
- **WhatsApp, Telegram, Instagram:** на эмуляторе не установлены, проверено в Google Messages и Contacts.
- **Юридический текст согласия.** Теперь в OpenAI уходит и голос. Строку на экране настройки голоса я обновил. Текст согласия и политику конфиденциальности должен поправить владелец.
- **Кэш повторов на сервере** хранится в памяти процесса. При нескольких репликах повтор может уйти в OpenAI ещё раз.
- **Голосовой ввод внутри самого приложения** (`DictationSheet`) по-прежнему системный, его не трогали.
