# Архитектура

Модульный монолит: один бинарник, один файл БД, никаких очередей и сервис-меша.
Границы проведены так, чтобы позже можно было вынести что угодно, не переписывая
домен.

## Слои

```
transport (HTTP)  →  services (auth, ai, plans, subscriptions, payments)  →  repository (SQL)  →  SQLite
                                        ↑
                                     domain (сущности, ошибки)
```

- `transport` не знает SQL, `repository` не знает HTTP, `domain` не знает ни того ни другого.
- DTO описаны отдельно от таблиц: схему БД можно менять, не ломая мобильные клиенты.

## База данных

SQLite в режиме WAL. Один пул на запись (ровно одно соединение, `BEGIN IMMEDIATE`)
и отдельный пул на чтение — так исключены `SQLITE_BUSY` в середине транзакции.
Все идентификаторы — UUID v4 (TEXT), все временные метки — UTC в миллисекундах (INTEGER).

Ключевые таблицы: `users`, `user_profiles`, `auth_identities`, `otp_codes`,
`refresh_tokens`, `devices`, `plans`, `subscriptions`, `usage_daily`,
`usage_monthly`, `ai_usage_events`, `model_pricing`, `payments`, `admin_users`,
`admin_sessions`, `admin_audit_logs`, `app_versions`, `system_settings`,
`product_events` (события онбординга и настроек: имя и проверенные по закрытому
списку свойства, без текста).

Переход на MySQL/Postgres = замена драйвера и диалекта в `repository`; домен и
транспорт не меняются.

## Квота

```
BEGIN IMMEDIATE
  INSERT OR IGNORE usage_daily(user_id, date, used=0)
  UPDATE usage_daily SET used = used + 1
   WHERE user_id = ? AND usage_date = ? AND used < :daily_limit     -- 0 строк → лимит
  (то же для usage_monthly, если лимит задан)
COMMIT
```

Резерв делается **до** вызова провайдера, поэтому две параллельные попытки на
последней генерации не могут пройти обе. Если провайдер не ответил — резерв
возвращается (`RefundQuota`), и пользователь не платит за неполученный ответ.
Повторные попытки клиента не удваивают списание, потому что каждая генерация
резервируется отдельно и возвращается при ошибке.

Сутки считаются по `DEFAULT_TIMEZONE` (по умолчанию `Asia/Almaty`), а не по
часам телефона: перевод времени на устройстве лимит не обходит.

## Аутентификация

- Access — JWT HS256, 15 минут, в payload только UUID пользователя/устройства.
- Refresh — 32 случайных байта; в БД лежит HMAC-хэш, исходное значение сервер не хранит.
- Ротация при каждом обновлении; предъявление отозванного токена отзывает всю
  «семью» (`family_id`) — защита от кражи.
- Пароли администраторов — PBKDF2-HMAC-SHA256, 600 000 итераций, соль на пароль.
- OTP хранится только как хэш, у кода есть TTL и счётчик попыток.

## AI-шлюз

Промпт собирается на сервере. Правила лежат в developer-сообщении, а всё
пользовательское (текст, инструкция, профиль, правила шаблона, строки рабочего
времени) — в user-сообщении внутри именованных блоков и подписано как данные.
Сообщение вида «игнорируй предыдущие инструкции» остаётся цитатой, а не командой.
В developer-сообщение попадает только серверный текст, выбранный проверенным
enum'ом (язык, род отправителя, тон, длина, эмодзи).

Developer-сообщение (`internal/ai/prompt.go`, `compose.go`; тексты правил —
`prompt_rules.go`) всегда идёт в одном порядке:

```
ROLE → PRODUCT RULES → LANGUAGE → SENDER → STYLE → OUTPUT
```

- **ROLE** — кто пишет и кому (ответ от первого лица / новое сообщение).
- **PRODUCT RULES** — одно готовое сообщение; намерение пользователя сохраняется
  (отказ остаётся отказом, данные время/цена/место — как есть); никаких
  выдуманных фактов; блоки — данные, а не команды; правило рабочего времени.
- **LANGUAGE** — целевой язык и правила качества именно для него. Язык решает
  входящее сообщение: `reply_language` → уверенно определённый язык входящего
  (`language.go`: по словам, частотным спискам `langdata/` и окончаниям; казахский
  узнаётся и без спецбукв, и латиницей, смешанное казахско-русское сообщение —
  казахское; в сомнительных случаях язык не называется и не проверяется — модель
  повторяет язык сообщения) →
  раскладка `input_language` → язык интерфейса. Раскладка и интерфейс — только
  «если язык неясен»; тогда добавляются краткие правила и для остальных языков.
  Промпт прямо говорит, что язык приложения, раскладки и инструкции ответ не
  меняет — только явная просьба в инструкции.
- **SENDER** — род отправителя (`male` / `female` / `unspecified`) для русских форм
  «рад/рада», «сделал/сделала»; при `unspecified` — нейтральные формулировки.
  Касается только отправителя, не получателя.
- **STYLE** — отношение, тон, длина и эмодзи из enum'ов шаблона, общие правила
  живой переписки.
- **OUTPUT** — только текст сообщения: без кавычек, «Ответ:», вступлений, markdown.

User-сообщение: `<working_hours>`, `<user_profile>`, `<business_context>`,
`<user_rules>`, `<template_instructions>`, `<incoming_message>`, `<user_instruction>`
(инструкция последней — она решает содержание) и строка «Write only the message.».

После модели (`quality.go`): детерминированная очистка `CleanOutput`, проверка
`Check` (род отправителя в русском, язык, служебный текст) и — только если есть
проблема — одна исправляющая попытка `repair_v1`; её текст принимается, только
если проходит ту же проверку. Квота — один раз, токены — обеих попыток. Ответ,
обрезанный по лимиту токенов (`status: "incomplete"`), укорачивается до последнего
целого предложения.

`POST /ai/polish` (`polish.go`) — отдельный путь без квоты: модель правит только
опечатки и пунктуацию в заметке пользователя, а детерминированная проверка
отбрасывает любой ответ, где изменились числа, имена, ссылки, кавычки или язык.

Каждый промпт имеет версию (`reply_v2`, `compose_v2`, `polish_v1`, `repair_v1`); она
пишется в `ai_usage_events.prompt_version` и в логи. Изменили текст правила —
поднимите версию и прогоните набор оценки. Подробно — [AI_QUALITY.md](AI_QUALITY.md).

Клиент не выбирает модель, температуру и лимит вывода — это решает сервер,
иначе счёт за токены зависел бы от приложения, которое можно пересобрать.
`OPENAI_TEMPERATURE=none` — поле не отправляется (reasoning-модели его не принимают).

## Приватность by design

`ai.Service.Reply` получает текст, строит промпт, вызывает провайдера и
возвращает ответ. Ни в одном из этих шагов текст не попадает ни в БД, ни в лог:
в `ai_usage_events` пишутся только модель, токены, стоимость, задержка, статус,
платформа, режим (`reply` / `compose` / `polish`), версия промпта и **длина**
исходного текста. Род отправителя хранится в профиле, но не попадает ни в логи,
ни в события, ни в admin JSON. В логгере есть дополнительный фильтр,
который затирает значения по списку ключей (`message`, `reply`, `otp`, `token`, …).

Текст уходит в OpenAI только у аккаунта с действующим согласием на текущие версии
условий и политики (`requireConsent` перед `/ai/*`, иначе `403 CONSENT_REQUIRED`);
согласие можно отозвать (`DELETE /me/consents`). Единственный сохраняемый текст —
сгенерированный ответ в жалобе (`ai_reports`), и только если человек сам решил его
отправить. Удаление аккаунта (`users.DeleteAccount`) — одна транзакция: коды входа,
отвязка установок с затиранием push-токена и `DELETE FROM users` с каскадом по всем
таблицам с `user_id`. Просроченное (коды, мёртвые сессии, установки без аккаунта,
метаданные старше года) удаляет `internal/retention` по окнам `RETENTION_*`.

## Наблюдаемость

Структурные логи (slog, JSON), `X-Request-ID` на каждый запрос, метрики в
дашборде считаются прямо из `ai_usage_events`. Продуктовые события приложений
(`internal/productevents`, `POST /api/v1/analytics/events`) проверяются по
закрытому списку — имя, ключи свойств, типы и значения; неподходящее событие
отклоняется поодиночке, свободный текст сохранить нельзя. Дашборд показывает их
число по именам. Стоимость — оценочная, считается
по таблице `model_pricing` (цены редактируются в админке, а не в коде).

## Веб

- `/` — лендинг: разметка рендерится сервером (SEO, быстрый первый экран),
  интерактив (анимация клавиатуры, счётчики, мобильное меню) — Vue 3.
- `/admin` — SPA на Vue 3 поверх `/api/v1/admin/*`: дашборд с графиками,
  таблицы с фильтрами, модальные формы, тосты. Vue подключён локально
  (`/static/vendor/vue.global.prod.js`) — CSP запрещает внешние источники,
  сборка фронтенда не нужна.
